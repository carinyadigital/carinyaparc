# Guiding Principles

Engineering rules for the Carinya Parc website (`apps/web`, Astro 7). [`ARCHITECTURE.md`](ARCHITECTURE.md) says where things live; this document says how they are built. The words **SHALL**, **MUST**, **SHOULD** and **MAY** carry their usual weight: the first two are checked in review, the last two are the default unless there is a stated reason.

1. **Zero JavaScript by default.** Pages and components **SHALL** be `.astro` files that render to static HTML. A page **MUST NOT** ship client-side JavaScript unless it contains an island or a small inline `<script>` for a progressive enhancement (sharing, scroll depth, the header). A component that only presents data **SHALL NOT** be written in React.

2. **Islands only for interaction.** React **MAY** be used only where the browser needs state, event handlers or browser APIs: today the contact, subscribe and event-signup forms, the subscribe modal and the consent gate. Islands **SHALL** live under `src/components/islands/`, **SHALL** be mounted from an `.astro` wrapper with an explicit `client:*` directive (`client:visible` for forms, `client:idle` for chrome), and **SHALL NOT** import server-only modules (`lib/api`, `lib/email`, `lib/mailerlite`, or anything that reads a secret). The endpoints accept form-encoded bodies as well as JSON so a form **MAY** fall back to a plain HTML `POST`; the islands do not set `action`/`method` today, so a no-JavaScript submit path is a goal, not a guarantee.

3. **Pages are thin.** A file under `src/pages/` **SHALL** contain only `getStaticPaths`, calls to the content helpers, metadata composition and component composition. Rendering **SHALL** be delegated to components; formatting and side effects **SHALL** live in `src/lib/`. UI components **SHALL NOT** fetch, send email, call a third party or hold business rules.

4. **Content through helpers.** Pages **SHALL** read collections through `src/lib/content/` (`getPublishedPosts`, `getPublishedRecipes`, `getUpcomingEvents`, …) rather than calling `getCollection` directly, so draft filtering, sorting and the summary shapes have one definition. Content **SHALL** be validated by the Zod schemas in `src/content.config.ts`; a schema change **MUST** be reflected in [`ARCHITECTURE.md`](ARCHITECTURE.md) §6.4. Internal URLs **SHALL** come from `src/lib/urls.ts` so every link carries its trailing slash.

5. **Metadata is composed, not hand-written.** Page metadata **SHALL** be produced by `generatePageMetadata` in `src/lib/metadata/`, which composes small functions (`generateTitle`, `generateCanonicalUrl`, `generateOpenGraph`, `generateTwitterCard`, `generateRobots`, `generateIcons`). `Base.astro` is the only file that turns that object into `<meta>` tags. Pages **MUST NOT** emit their own `<title>` or `<meta>` elements.

6. **Structured data per type.** JSON-LD **SHALL** be generated by discrete pure functions in `src/lib/schema/` (Organization, BreadcrumbList, LocalBusiness, Article, Recipe). `Base.astro` emits Organization on every page; pages add the rest through `<JsonLd />`, which assembles a single `@graph`. New page types **SHOULD** add a generator and a test rather than inline JSON.

7. **Environment configuration.** Every variable **MUST** be listed in `apps/web/.env.example`, the `env` lists in `turbo.json` and the `turbo/no-undeclared-env-vars` allow list in `apps/web/eslint.config.mjs`. Variables exposed to the browser **MUST** be prefixed `PUBLIC_` and **SHALL NOT** contain secrets. Secrets **SHALL** be read only in server code (`src/lib/api/`, `src/lib/email/`, `src/lib/mailerlite/`, `astro.config.mjs`). A build **MUST** succeed with no secrets set; optional integrations **SHALL** degrade with a clear error rather than crash.

8. **Static output, explicit exceptions.** `output` is `static`. A route **MAY** opt into on-demand rendering with `export const prerender = false` only when it must act on a request: today the four `/api/*` endpoints and the 410 handlers for retired routes. Such an endpoint **SHALL** respond with `Cache-Control: no-store` and **SHALL NOT** read a database; there is none.

9. **Security is generated and tested.** Response headers and the CSP **SHALL** be defined once in `src/lib/security/` and reach production through the generated `vercel.json` and the Build Output config merge in `astro.config.mjs`. A new form endpoint **MUST** follow the existing handler pattern: Zod validation, honeypot, minimum submission time, in-memory rate limit, sanitisation, no personal data in logs. Headers, CSP directives, validation and rate limiting **SHALL NOT** be weakened to make a test, a build or a third-party script work.

10. **Type safety.** TypeScript strict mode (`astro/tsconfigs/strict`) is **REQUIRED** and `astro check` **MUST** pass. `any` **SHOULD NOT** appear. Types **SHALL** live beside the module that owns them (`types.ts` in a folder, or inline in a single-file module); collection types **SHALL** come from `CollectionEntry<'name'>`.

11. **Testing.** Automated tests are **REQUIRED** for endpoint handlers, validation schemas, sanitisation, security generators, metadata and JSON-LD generators, and any island that holds state. Tests **SHALL** be colocated as `*.test.ts` / `*.test.tsx` under `src/`. Checks that need the built site (links, images, CSP hosts, headers, parity with the production baseline) **SHALL** live under `apps/web/tests/` and run against `dist/` after `astro build`. Presentational components **SHOULD NOT** be unit tested.

12. **Styling.** Design tokens and the Tailwind CSS 4 theme **SHALL** live in `packages/carinya-theme` and be imported once in `src/styles/globals.css`. Site-wide component CSS **SHALL** live in `src/styles/components.css`; page-specific CSS **SHALL** live in `src/styles/pages/` and be imported by the page that uses it. Components **SHOULD** use utility classes; dynamic class merging **MUST** use `cn()` from `src/lib/cn.ts`. The app **SHALL NOT** redefine a token.

13. **Images.** Content images **SHALL** be referenced from frontmatter and rendered with `astro:assets` so they are resized and given `width`/`height`. Page photography **SHALL** be imported from `src/assets/images/`. Plain `<img>` from `public/images/` **MAY** be used only for fallbacks and placeholders. Above-the-fold images **SHOULD** be `loading="eager"` with `fetchpriority="high"`; everything else lazy.

14. **Performance.** The build **SHALL** stay hermetic: no network calls at build time beyond what integrations do themselves (the Sentry source-map upload when `SENTRY_AUTH_TOKEN` is set). Third-party scripts (GTM, Vercel Analytics, Speed Insights) **SHALL** load only from `ConsentGate` after consent. Large dependencies inside an island **SHOULD** be dynamically imported.

15. **Accessibility.** Pages and components **SHALL** use semantic HTML and landmark elements (`<main>`, `<nav>`, `<article>`), with ARIA only where native semantics fall short. All images **MUST** have meaningful `alt` text (content images via `imageAlt`), interactive elements **MUST** be keyboard-navigable with a visible focus state, and form fields **MUST** have associated labels and error messages.

16. **Copy.** User-facing text **SHALL** be Australian English and follow `brand/voice.md`. Error messages returned by endpoints **SHOULD** tell the visitor what to do next and **SHALL NOT** reveal internal details.

17. **Documentation.** A change to routes, folders or architecture **MUST** update [`ARCHITECTURE.md`](ARCHITECTURE.md); technical debt **SHALL** be recorded only in [`ARCHITECTURE.md`](ARCHITECTURE.md) §10. These principles **SHOULD** be amended in the same pull request that first departs from them.
