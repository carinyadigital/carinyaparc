# Guiding Principles

Engineering rules for the Carinya Parc website. The architecture record describes the system; this document is how it is built. The words **SHALL**, **MUST**, **SHOULD** and **MAY** carry their usual weight: the first two are checked in review, the last two are the default unless there is a stated reason.

1. **Zero JavaScript by default.** Pages **SHALL** render to static HTML. A page **MUST NOT** ship client-side JavaScript unless it contains an interactive island or a small progressive enhancement. A component that only presents data **SHALL NOT** be a client component.

2. **Islands only for interaction.** A client component **MAY** be used only where the browser needs state, event handlers, or browser APIs. Islands **SHALL** be mounted explicitly from a static page and **SHALL NOT** import server-only code or anything that reads a secret. A form **MAY** accept a plain submission as well as JSON so it can work without JavaScript; a no-JavaScript submit path is a goal, not a guarantee.

3. **Pages are thin.** A page **SHALL** contain only routing, content loading, metadata, and composition. Rendering **SHALL** be delegated to components. Formatting and side effects **SHALL** live in shared modules. A UI component **SHALL NOT** fetch, send email, call a third party, or hold business rules.

4. **Content through helpers.** Pages **SHALL** read published content through the shared content helpers, so draft filtering, sorting, and summary shapes have one definition. Content **SHALL** be validated by schema. A schema change **MUST** be recorded in the architecture record. Internal URLs **SHALL** be built in one place so every link carries its trailing slash.

5. **Metadata is composed, not hand-written.** Page metadata **SHALL** be produced by one composer. One layout **SHALL** turn that object into meta tags. Pages **MUST NOT** emit their own title or meta elements.

6. **Structured data per type.** JSON-LD **SHALL** be generated by discrete pure functions, one per type. The layout emits the organization on every page; pages add the rest through one component that assembles a single graph. A new page type **SHOULD** add a generator and a test rather than inline JSON.

7. **Environment configuration.** Every variable **MUST** be declared for the build, the task runner, and the linter. A variable exposed to the browser **MUST** be marked public and **SHALL NOT** contain a secret. Secrets **SHALL** be read only in server code. A build **MUST** succeed with no secrets set. An optional integration **SHALL** degrade with a clear error rather than crash.

8. **Static output, explicit exceptions.** The site **SHALL** be static. A route **MAY** render on demand only when it must act on a request. Such a response **SHALL** not be cached and **SHALL NOT** read a database.

9. **Security is generated and tested.** Response headers and the content security policy **SHALL** be defined once and generated into the deployment configuration. A new form endpoint **MUST** follow the existing handler pattern: schema validation, a honeypot, a minimum submission time, an in-memory rate limit, sanitisation, and no personal data in logs. Headers, the policy, validation, and rate limiting **SHALL NOT** be weakened to make a test, a build, or a third-party script work.

10. **Type safety.** Strict typing **MUST** pass. `any` **SHOULD NOT** appear. Types **SHALL** live beside the module that owns them. A collection's types **SHALL** come from that collection's entry type.

11. **Testing.** Automated tests are **REQUIRED** for endpoint handlers, validation, sanitisation, security generators, metadata and structured-data generators, and any island that holds state. Tests **SHALL** sit beside the module they cover. Checks that need the built site **SHALL** run against the build output. Presentational components **SHOULD NOT** be unit tested.

12. **Styling.** Design tokens and the theme **SHALL** live in one shared theme and be imported once. Site-wide component styles and page-specific styles **SHALL** stay separate. Components **SHOULD** use utility classes. Dynamic class names **MUST** be merged by the shared helper. The app **SHALL NOT** redefine a token.

13. **Images.** A content photograph **SHALL** be referenced from its entry and rendered through the image pipeline so it is resized and given dimensions. Post and recipe photographs **SHALL** use a shared preset for their layout, so a card does not download a hero. One image service **SHALL** encode those files as WebP. A second image service **MUST NOT** be added. A content photograph **SHALL** have alt text. A decorative image whose title is already a heading **SHALL** use an empty alt. Page photography **SHALL** be imported so the build can optimise it. A plain image element **MAY** be used only for a fixed-URL placeholder. A share image **SHALL** be a centre-cropped JPEG produced at build time from an imported photograph. Above-the-fold images **SHOULD** load eagerly and with high priority; everything else lazy.

14. **Performance.** The build **SHALL** stay hermetic: no network calls at build time beyond what an integration does itself. Third-party analytics scripts **SHALL** load only after consent. A large dependency inside an island **SHOULD** be loaded on demand.

15. **Accessibility.** Pages and components **SHALL** use semantic HTML and landmarks, with ARIA only where native semantics fall short. Every image **MUST** have meaningful alt text. Interactive elements **MUST** be keyboard-navigable with a visible focus state. Form fields **MUST** have associated labels and error messages.

16. **Copy.** User-facing text **SHALL** be Australian English and follow the brand voice. An error message **SHOULD** tell the visitor what to do next and **SHALL NOT** reveal internal details.

17. **Documentation.** A change to routes, structure, or architecture **MUST** update the architecture record. Technical debt **SHALL** be recorded only there. These principles **SHOULD** be amended in the same change that first departs from them.
